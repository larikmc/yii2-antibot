[![Software License](https://img.shields.io/badge/license-MIT-brightgreen.svg)](LICENSE.md)
[![Latest Version](https://img.shields.io/badge/release-v1.5.7-blue.svg)](https://github.com/larikmc/yii2-antibot/releases/tag/v1.5.7)
[![PHP](https://img.shields.io/badge/PHP-8.0%20|%208.1%20|%208.2%20|%208.3%20|%208.4%20|%208.5-blue)](https://php.net)
[![Yii2](https://img.shields.io/badge/Yii2-2.0.x-orange.svg)](https://yiiframework.com)

**Высокопроизводительный автономный модуль антибот-защиты для Yii2 с визуальной аналитикой на Apache ECharts.**  
Обеспечивает комплексную защиту веб-сайта от парсеров, AI-краулеров, фейковых поисковиков, спам-ботов и HTTP-флуда с типичным временем проверки **~0.05–0.35 мс** на стандартном PHP-стеке, не требуя обязательного Redis, Nginx Lua или внешних платных облачных сервисов.

## ⚡ Ключевые возможности v1.5.7

### 1. Интерактивная визуальная аналитика на Apache ECharts (v1.5.7)
- **4 информативных графика в административной панели:**
  1. *Динамика подозрительной активности (Line/Area Chart)*: временные ряды мониторинга, реальных блокировок, Rate Limit и проверок (Challenge). Переключатель периодов: **24 часа** (почасовая группировка), **7 дней**, **Вся доступная история**. События со статусом `simulated: true` строго отображаются как мониторинг и не искажают статистику реальных блокировок.
  2. *Распределение действий (Donut Chart)*: соотношение категорий действий в учтённых событиях журнала с выводом общего числа событий в центре кольца и расчётом процентов.
  3. *Основные причины срабатываний (Horizontal Bar Chart)*: топ-8 категорий срабатываний (CLI-библиотеки, поддельные боты, AI-краулеры, скраперы, Rate Limit, ловушки) с понятными русскими названиями.
  4. *Самые атакуемые маршруты (Horizontal Bar Chart)*: топ-10 URL, подвергающихся подозрительным запросам. В целях безопасности query string и токены удаляются, исключая утечку приватных данных и XSS.
- **Нулевая дополнительная нагрузка на публичный HTTP-путь:**
  - Графики не выполняют никакой агрегации при публичных запросах посетителей сайта.
  - Лог-файлы (`antibot_events.jsonl`) читаются эффективно с конца через `tailFile` в один проход только при открытии панели администратора.
  - Агрегированный датасет кэшируется на **120 секунд** с защитой от спам-пересчётов при принудительном обновлении (cooldown).
- **Автономность и доступность:**
  - Локальный минифицированный бандл `echarts.common.min.js` (Apache License 2.0 / NOTICE сохранены в пакете). Никаких внешних CDN!
  - Не требует Node.js или npm при установке пакета.
  - Респонсивный адаптивный дизайн и табличные текстовые fallback-представления для доступности.

### 2. Безопасность для SEO и верификация поисковиков (Reverse DNS PTR + Anti-DNS-DoS)
- Легитимные поисковые роботы (Яндекс, Google, Bing, Mail.ru) верифицируются через Reverse DNS и защищены от блокировок при наличии DNS-бюджета.
- **Изолированный кэш-неймспейс v3 и защита от CIDR-спуфинга:**
  - Кэш верификации роботов использует префикс `antibot_rdns_v3_`, что гарантирует автоматическую немедленную инвалидацию устаревших записей предыдущих версий.
  - Пре-фильтр использует точные официальные подсети Googlebot (`GOOGLEBOT_CIDRS`, 317 подсетей IPv4/IPv6) и Bingbot (`BINGBOT_CIDRS`, 28 подсетей IPv4).
  - Верифицированные краулеры мгновенно получают статус `STATUS_VERIFIED` с **0 DNS-запросов** и кэшируются на 24 часа. Статус верификации поисковика никогда не даёт доступа к закрытым разделам сайта.
  - Для Яндекса сохранена обязательная двухсторонняя DNS-проверка (PTR + A/AAAA lookup).
- **Физические блокировки ОС-слотов и автоочистка зависших записей:**
  - Слоты удерживаются на физических файлах блокировок через `flock(LOCK_EX | LOCK_NB)` на всё время проверки и автоматически освобождаются ядром ОС при завершении процесса.
  - Concurrency-лимит: не более 3 одновременных in-flight DNS-запросов на весь сервер.
  - Single-flight дедупликация: исключены повторные одновременные проверки одного и того же IP.

### 3. Чёткая иерархия конфигурации и идемпотентный Bootstrap
- **3 уровня приоритетов настроек:**
  1. *Явно сохранённые администратором настройки* в JSON-файле хранилища (`antibot.json`, высший приоритет).
  2. *Конфигурация приложения Yii2* (свойства компонента в `config/web.php` или `common/config/main.php`).
  3. *Значения по умолчанию* в коде компонента.
  - Дефолты хранилища никогда не переопределяют настройки, явно переданные разработчиком в конфигурации Yii2.
  - Безопасный fallback: нераспознанный режим автоматически нормализуется в `standard` и никогда скрыто не включает `strict`.
- **Идемпотентный Bootstrap без дублирования событий:**
  - Встроенный guard `_isBootstrapped` гарантирует однократную регистрацию обработчиков событий `EVENT_BEFORE_REQUEST` и `EVENT_BEFORE_ACTION`, даже если модуль зарегистрирован одновременно через Composer extension bootstrap и массив `bootstrap => ['antibot']`.
  - Консольные команды (`yii\console\Application`) изолированы от запуска веб-антибота.

### 4. Защита от подмены IP и безопасные прокси (`trustedProxies`)
- Заголовки прокси (`CF-Connecting-IP`, `X-Forwarded-For`, `X-Real-IP`) принимаются **только** от доверенных прокси-серверов (`trustedProxies`, поддерживается нотация CIDR).
- По умолчанию список `trustedProxies` пуст (`[]`): заголовки прокси строго игнорируются, клиентский IP берётся только из `REMOTE_ADDR`.
- Значение `['127.0.0.1']` следует указывать **только** тогда, когда перед сайтом действительно работает локальный обратный прокси (Nginx), который корректно очищает входящие заголовки `X-Forwarded-For`.
- Исключена подмена loopback-адресов (`127.0.0.1`, `::1`): заголовочные loopback-адреса отбрасываются.

### 5. Адаптивный Rate Limiter и Weighted Rate Limiter
- **`CacheLimiter` (по умолчанию)**: неблокирующий dual-bucket алгоритм с пакетным чтением через `multiGet`. Предотвращает исчерпание пула PHP-FPM под нагрузкой. Безопасно деградирует (fail-open) при сбое кеша.
- **`RedisLimiter` (опционально)**: атомарный sliding-window алгоритм на Lua-скриптах Redis.
- **`WeightedRateLimiter`**: взвешенная тарификация запросов в зависимости от ресурсоемкости маршрута (главная = 1 балл, поиск = 5 баллов, тяжелые фильтры = 8 баллов).

### 6. Автономный Proof-of-Work (PoW) и JS Challenge
- **100% локальный PoW-челлендж** без Cloudflare / reCAPTCHA: вычисление частичной коллизии SHA-256 в браузере клиента через нативный `crypto.subtle.digest()`.
- Три уровня сложности: `light` (~50-100 мс), `medium` (~300-800 мс), `strong` (~2-4 с).
- Криптографическая защита от повторного использования (replay protection) и проверка валидности решения **до** сжигания семени.
- Автоматический пропуск API/AJAX-запросов с выдачей чистого JSON `403` / `429`.

### 7. Поведенческий анализ (`BehaviorAnalyzer`) и Risk Engine
- Скользящее окно активности (до 15 запросов на IP): выявление быстрых переходов (< 250 мс), аномальной вариативности URL, серий 404/500 ошибок и поискового спама.
- Детерминированная шкала риска (0–100 баллов) с градацией реакций (мониторинг, троттлинг, PoW, блокировка).
- Дебаунс событий мониторинга (интервал 3 сек для повторных записей одного IP) устраняет дисковую блокировку при высоконагруженных всплесках.

### 8. Невидимые Honey URLs и защищенный Honeypot
- Невидимые для людей ссылки-ловушки (`HoneyTrapWidget`), при переходе по которым парсеры мгновенно получают штрафной балл риска и отправляются в карантин.
- Криптографически подписанный `HoneypotWidget` для защиты контактных форм и регистрации от спам-ботов. Метод `HoneypotWidget::validateSubmission()` для проверки в одну строку.

### 9. Отказоустойчивость: межпроцессный Fail-Safe Circuit Breaker
- Межпроцессный трехуровневый предохранитель (`CLOSED`, `OPEN`, `HALF_OPEN`) с атомарным управлением переходами через неблокирующий `flock(LOCK_EX | LOCK_NB)` (таймаут ожидания < 5 мс).
- **Строгий Fail-Safe режим:** при невозможности взятия файловой блокировки контур гарантированно не выполняет мутирующий callback, не генерирует зондовых токенов и возвращает безопасное fallback-состояние.
- В состоянии `HALF_OPEN` право на пробный запрос выдается строго монопольно одному рабочему процессу только при подтвержденной блокировке на диске.

### 10. Статистика Best-Effort и выборка Reservoir Sampling (Algorithm R)
- **Reservoir Sampling Algorithm R:** корректная равномерная выборка ёмкостью $K = 100$ (`METRIC_SAMPLE_RESERVOIR_CAPACITY`). Каждый запрос на шаге $N$ включается в выборку со строго одинаковой вероятностью $K/N$.
- **Отсутствие вымышленных значений:** при отсутствии статистики возвращается строго `null` («Нет данных») без фиктивных значений.
- **Честный учёт пропусков:** показатель `dropped_records` документирован как частичный диагностический счётчик отказов блокировки диска (`exact_count_unknown`).

### 11. Встроенная самодиагностика (`SelfTest`)
- Экспресс-проверка окружения в админ-панели: версии PHP, расширений, прав на запись, энтропии ключа, доступности DNS, физических слотов DNS, актуальности официальных CIDR-подсетей, кэш-пространства `antibot_rdns_v3_`, fail-safe токенов Circuit Breaker и состояния резервуара метрик.

## 🚀 Быстрый старт за 3 шага

### Шаг 1. Подключение компонента (`common/config/main.php` или `frontend/config/main.php`)

```php
'components' => [
    'antibot' => [
        'class' => \larikmc\antibot\Antibot::class,
        'enabled' => true,
        'mode' => 'monitoring', // Рекомендуется 'monitoring' для первого запуска (только логирование без блокировок)
        
        // Опциональный ключ HMAC (по умолчанию генерируется автоматически):
        // 'secretKey' => 'your-secure-random-32-byte-secret-key',
        
        // Доверенные прокси (Reverse Proxies):
        // По умолчанию список пуст ([]): заголовки X-Forwarded-For и CF-Connecting-IP строго
        // игнорируются, клиентский IP берётся только из REMOTE_ADDR (защита от подмены IP).
        // Если сайт работает за локальным Nginx на том же сервере: ['127.0.0.1']
        // Если сайт за внешним балансировщиком/CDN: укажите точные доверенные IP балансировщиков.
        'trustedProxies' => [],
    ],
],
```

> [!NOTE]
> При установке через Composer модуль регистрируется автоматически благодаря `extra.bootstrap` в `composer.json`. Добавлять `'antibot'` в массив `'bootstrap'` вашего приложения не требуется. Встроенная защита от повторного вызова исключает дублирование проверок при любой комбинации настроек.

### Шаг 2. Подключение модуля управления (`backend/config/main.php`)

```php
'modules' => [
    'antibot' => [
        'class' => \larikmc\antibot\Module::class,
        // Вариант 1: С использованием RBAC (рекомендуется)
        'accessPermission' => 'antibot.manage',
        
        // Вариант 2: По роли администратора
        // 'accessRoles' => ['admin'],
        
        // Вариант 3: Пользовательский callback
        // 'accessCallback' => function (\yii\web\User $user): bool {
        //     return $user->identity && $user->identity->isAdmin();
        // },
    ],
],
```

> [!WARNING]
> Никогда не используйте `'accessRoles' => ['@']` на боевом сайте: это предоставит доступ к панели управления антиботом любому авторизованному посетителю сайта.

Добавьте пункт меню в административную панель (`larikmc/yii2-admin`):

```php
[
    'icon' => 'shield',
    'label' => 'Антибот',
    'url' => ['/antibot'],
],
```

### Шаг 3. Подключение виджетов во Frontend (`frontend/views/layouts/main.php`)

Внутри `<head>`:

```php
<?= \larikmc\antibot\widgets\AntibotWidget::widget() ?>
```

Перед закрывающим тегом `</body>` (для размещения скрытых ссылок-ловушек для спам-ботов):

```php
<?= \larikmc\antibot\widgets\HoneyTrapWidget::widget() ?>
```

## 🛡️ Защита веб-форм (Honeypot)

Для защиты контактных форм, регистрации и комментариев без раздражающих капч:

```php
<?php $form = ActiveForm::begin(); ?>

    <?= \larikmc\antibot\widgets\HoneypotWidget::widget() ?>

    <?= $form->field($model, 'name') ?>
    <?= $form->field($model, 'email') ?>
    ...
<?php ActiveForm::end(); ?>
```

В контроллере:

```php
if (Yii::$app->request->isPost) {
    if (!\larikmc\antibot\widgets\HoneypotWidget::validateSubmission()) {
        throw new \yii\web\ForbiddenHttpException('Спам-активность отклонена.');
    }
}
```

Или с выводом ошибки через flash-сообщение:

```php
if (Yii::$app->request->isPost) {
    $check = \larikmc\antibot\widgets\HoneypotWidget::validate(Yii::$app->request->post());
    if (!$check['valid']) {
        Yii::$app->session->setFlash('error', $check['error']);
        return $this->refresh();
    }
}
```

## ⚙️ Тонкая настройка маршрутов (Action Filter & Cost Charging)

Для ограничения частоты на критичных экшенах:

```php
public function behaviors(): array
{
    return [
        'antibot' => [
            'class' => \larikmc\antibot\filters\AntibotFilter::class,
            'maxRequests' => 5,
            'window' => 60,
            'only' => ['login', 'signup'],
        ],
    ];
}
```

Для ручного списания баллов нагрузки при выполнении ресурсоёмких операций:

```php
public function actionGeneratePdfReport()
{
    // Списываем 15 баллов нагрузки у текущего клиента
    \larikmc\antibot\Antibot::chargeCost(15, 'PDF Export');
    
    // Генерация отчета...
}
```
